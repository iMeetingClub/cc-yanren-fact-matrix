自由讨论 1：宿舍餐费报价核算
事实
1. 讨论中出现“只看法币/人民币对应关系”的说法：给人民币每人46；工商人直接给法币为6。
2. 关于NT需求：有人认为NT需求来自我方而非对方。
3. 按总账核算：支出人民币减少；NT被认为有多余可用于支付宿舍。
4. 已知一餐为18，拆分为8人民币+10NT。
5. 宿舍给主办方报价口径存在两种：总数106与79，且被认为79更便宜。
6. 曾出现口径反转分歧：8NT+10人民币 vs 8人民币+10NT。
7. 总计口径曾表述为46元人民币加60NT。
判断
1. 认为只看法币时，人民币金额可视为减少；但若按工商人直接给则法币为6。
2. 认为对方没有NT需求，因此对“免掉60NT”不会有回应。
3. 认为按总账核算后NT可能存在冗余。
4. 对之前报价理解是否正确存在不确定。
5. 宿舍给主办方的整体报价较高。
6. 核算后某方（79口径）相对更便宜。
观点
1. 需要先同步清楚报价信息与核算口径，避免基于未对齐数据判断。
2. 拆分口径统一后，才能判断报价更合理。
3. 在信息整理清楚前应避免急于下结论。
建议
1. 核对并统一一餐18的拆分口径（8人民币+10NT），再校准“两餐/总计”。
2. 复核总数106与79两种口径的来源及换算逻辑，确认是否存在口径反转。
3. 如讨论“60NT是否可减少”，需先确认双方对NT的实际需求与可否调整。
4. 若总账显示NT冗余，可考虑将多余NT用于支付宿舍（前提是口径一致）。

自由讨论 3：宿舍报价与成本口径核对
事实
1. 需要澄清“30+40 NT”与“一床两餐”是否对应同一产品组合。
2. 希望将“30+40 NT”的形成机制、折算口径与补贴归属讲清。
3. 提出两个待答问题：领队为何需要合作社接收“南糖豆/奶糖豆”。
4. 提出待答问题：高丽姐原本报给尹队的价格到底是多少，并给出一个版本。
5. 新增发言认为“106”是基于某种原因/逻辑组合出来的。
6. 新增发言认为合作社接收NT后，营队应获得更好结果而非仅数量价值。
判断
1. 当前对补贴与折算方式的理解可能与对方存在偏差。
2. “106”具有内在逻辑，但目前难以从数字对应到“目标价值”。
3. 需要进一步梳理与合作社、住在那边伙伴的收费逻辑。
观点
1. 报价与成本对账前应先澄清组合价形成机制与各方角色口径。
2. 应以双方一致的费用列项（宿舍一晚、合作社接HONT价格等）作为对齐基础。
3. 接收NT后应带来可感知的价值，而不仅是数量层面的变化。
建议
1. 将“30+40 NT”与“一床两餐”逐项映射到同一时间单位与费用构成。
2. 补充说明40 NT对应的30人民币部分由谁承担、补贴如何计入成本口径。
3. 先回答：领队为何需要合作社接收“南糖豆/奶糖豆”的原因。
4. 再给出：高丽姐原本报给尹队的价格版本，便于在左边对齐逻辑。
5. 确认各方角色与口径一致后，再核算79与106差异，并解释接收NT带来的“目标价值”如何落地。

3. 共创人侧存在基底发放与共创任务，可通过主线/支线任务提升获得 NTK。
4. 共创人通过“造服装方”购买画作，形成默认流通链路（如 STEP3 到 STEP4）。

6. 文案表述倾向使用“组合的组”，以说明具体建造房的对象。

1. 该链路设计对实现“采购帮厨/务农服务”有帮助。
2. 当前理解的任务逻辑与当时共创人设置相匹配，因此原链路可作为解释基础。
3. 人工费部分预计体现为增值，但价值构成需进一步说明。
观点
1. 说明口径时应强调采购参数服务与链路流通的目的。
2. 文案措辞可用“组合的组”来避免歧义，突出参与组合与建造房的对应关系。

2. 将共创人侧的基底发放、主线/支线任务与共创任务获得 NTK 的逻辑串联进说明。
3. 在文案中按“组合的组”表述，明确对应到具体建造房的对象。
4. 对人工费增值环节先保留框架，后续再补充具体计算与对应服务项。
自由讨论 5：共创人归属与宿舍口径
事实
1. 若按审核与报销流程，对方愿意先逐笔付人民币则可执行。
2. 提到的时间口径：3天过后、3天以内可提报任务。
3. 在3天内做报销需提供“组合价”（打包价格）。
4. 对方开任务时需写明住三天金额与其支付给主办方金额。
5. 对方需按实际吃的餐数列出对应餐费金额。
6. 任务由主办方审核后，确认对方确已支付并带任务与宣传后予以报销。
7. 报销通过把人民币返还给对方实现；收到的人民币审核费用于报销。
8. 认为NT逻辑与上述审核费/报销返还流程一致。
判断
1. 认为只要对方愿意先付人民币，审核与报销流程就不会有问题。
2. 认为“组合价”是将3天内花销做成报销所需的表达方式。
3. 认为住天数与餐数等明细能支撑审核后报销的核对。
4. 认为NT对应的本质逻辑与审核费用于报销一致。
观点
1. 倾向通过审核后再报销，并把流程口径讲清楚以便对方理解。
2. 认为任务发起方应在任务开立时提供可核对的明细（住天、餐数、金额）。
3. 认为“组合价/打包价格”能降低对外沟通与核算的歧义。
建议
1. 对外沟通采用审核与报销：对方先逐笔付人民币，完成后再返还报销。
2. 要求对方在开任务时填写住天与金额、餐数与对应金额，便于审核核对。
3. 在3天内将花销做成报销时提供“组合价”（打包价格）以形成可报销口径。
4. 在审核环节确认：对方确已支付、携带任务及宣传后再执行报销返还。

自由讨论 8：审核费与住宿费回收口径
事实
1. 费用通过支付宝扫码分阶段发出：每餐扫一次，逐步把3天人民币费用收完
2. 共创人报销时可在这三天延时的住宿和餐饮期间开任务并提供材料
3. 任务内容包含共创人准备的视频，由主办方审核宣传内容
4. 审核确认后，共创人需在同一时间放上等量NT，主办方完成任务与审核
5. NT兑换后，由小荷包返还人民币给共创人，且再由我们用NT换回人民币
6. 最后人民币作为主办方资金用于与供应商谈15天延期的总体价格/服务补充
7. 审核费给斌哥，斌哥对小人民币，认为该链路已算清楚
判断
1. 回收口径可能因AI整理出错，需要重新叙述校验
2. 回收方式取决于审核费/住宿费与NT去处的匹配关系
3. 回收过程中存在口径或去处弄错的风险，需确认一一对应关系
4. 共创后可能仍收到“NT”去处的款项/凭证，影响回收结清判断
观点
1. 应先把费用计算与报销/审核/发放的链路理清，再确定回收口径
2. 回收谈判应以主办方审核与等量NT放置的机制为依据
3. 口径固化（如按小荷包处理）有助于明确两清条件
4. 若存在错配风险，应优先核查账务对上逻辑而非直接谈回收
5. 该回收/发放链路整体OK、已算清楚
建议
1. 核对支付宝扫码与任务起止时间（可延后到25号后）是否影响费用归集
2. 按“主办方审核宣传→同时间放等量NT→我们用NT换回人民币→小荷包返还”梳理审核费/住宿费对应关系
3. 固化住宿费按“小荷包”口径打回并明确两清条件
4. 针对“共创后收到NT”的情况，核查是否与审核费回收口径一致或存在错配
5. 补充核对：审核费与住宿费是否等量且对应同一类支出关系，再据此与对方沟通回收
6. 再分别叫人对口确认（如由若曦与厂里人员一起对接）
